# 翻译审校网页工具

[使用说明](../_doc/README.zh-CN.md) · [开发文档](../_doc/DEVELOPMENT.md)

翻译与审校使用本地网页工作区，不要手工编辑翻译或审校 JSON。

## 启动

先按[开发文档](../_doc/DEVELOPMENT.md)准备 SDK、Visual Studio 和 uv，再从仓库根目录运行：

```powershell
uv run --project .\_localization\tools --locked aetext review
```

首次运行会准备 Python 环境。使用期间保持终端运行；浏览器未自动打开时，打开 `AeText review:` 后显示的本地网址。

**界面语言**控制网页显示语言，**译文语言**选择当前编辑的译文。NF 主线效果提供简体中文译文；Settings 的原文为中文，可审校英文和日文窗口文字。

## 扫描

- 首次打开本仓库时，选择 **扫描 > 扫描所有插件源码**。
- 只处理一个效果时，选中它并选择 **扫描 > 扫描当前插件源码**。
- 修改了源码文字或包装宏，或页面提示源码数据过期时，重新扫描对应插件。

左侧的 **NF 主线效果** 按 NF 分类显示效果；模板／测试和 Settings 单独列出。

## 文件位置

效果翻译保存在 `_localization/catalog/<分类>/<工程名>.json`，审校状态按相同相对路径保存在 `_localization/review-state/`。主线效果使用 NF 类别，三个开发工程使用 `(_SDK)`。Settings 的两个 `Settings.json` 直接位于各自根目录；其工程和插件输出仍使用 `_Support`。

目录迁移会同时移动翻译与审校文件，保持内容不变。更新源码后若翻译文件路径发生变化，请重新扫描对应插件以刷新源码缓存；原文、译文及审校依据未变的条目保留有效审校状态。

## 翻译与审校

1. 选择插件和译文语言。
2. 在 **译文** 中填写翻译；保留原文时启用 **使用原文**。
3. 下拉菜单文字通过 **编辑下拉项…** 修改，保持选项数量和顺序。
4. 确认文字后，将 **状态** 设为 **已校对**。

原文或译文发生变化后，原有审校状态可能需要重新确认。先核对当前内容，再标记已校对。

## 保存与重新读取

`*` 表示有未保存的修改。使用 **保存当前插件** 或 **保存全部改动** 完成保存。

如果文件被其他窗口或工具更新，先保留需要的草稿，再使用 **重新读取翻译文件** 读取最新内容并核对后保存。

## 检查发布审校

保存后，选择效果或 Settings，并使用 **扫描 > 检查当前插件发布审校**。根据提示处理缺译、无效内容或待校对条目。

该操作检查当前插件。整套正式构建仍使用 `BuildPlugins.bat publication`，由构建流程统一检查。

## 停止或重新打开

保存修改后，在终端按 `Ctrl+C` 停止服务；再次使用时重新运行启动命令。
