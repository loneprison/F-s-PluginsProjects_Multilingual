# 翻訳レビュー Web ツール

[使用ガイド](../_doc/README.ja.md) · [開発ガイド](../_doc/DEVELOPMENT.ja.md)

翻訳とレビューにはローカル Web ワークスペースを使用し、翻訳やレビューの JSON を手作業で編集しないでください。

## 起動

[開発ガイド](../_doc/DEVELOPMENT.ja.md)に従って SDK、Visual Studio、uv を準備し、リポジトリのルートから実行します。

```powershell
uv run --project .\_localization\tools --locked aetext review
```

初回実行時に Python 環境が準備されます。使用中はターミナルを動かしたままにしてください。ブラウザーが自動で開かない場合は、`AeText review:` の後に表示されるローカル URL を開きます。

**表示言語** は Web UI、**翻訳言語** は編集する翻訳を選びます。NF メインラインエフェクトには簡体中国語訳があります。Settings の原文は中国語で、設定ウィンドウの英語訳と日本語訳をレビューできます。

## スキャン

- このリポジトリを初めて開く場合は、**スキャン > すべてのプラグインソースをスキャン** を選びます。
- 1 つのエフェクトを処理する場合は、選択して **スキャン > 現在のプラグインソースをスキャン** を選びます。
- 原文やラッパーを変更した場合、またはソースデータが古いと表示された場合は、該当プラグインを再スキャンします。

左側の **NF メインラインエフェクト** は NF の分類ごとに表示されます。テンプレート／テストと Settings は別に表示されます。

## ファイルの保存場所

エフェクトの翻訳は `_localization/catalog/<カテゴリ>/<プロジェクト名>.json` に、レビュー状態は `_localization/review-state/` 以下の同じ相対パスに保存します。メインラインエフェクトには NF カテゴリを、3 つの開発プロジェクトには `(_SDK)` を使用します。Settings の 2 つの `Settings.json` は各ルート直下に置き、ソリューションフォルダーとプラグイン出力は `_Support` を使用します。

ディレクトリ移動では翻訳とレビュー状態を一緒に移動し、内容は変更しません。ソースツリーの更新後に翻訳ファイルのパスが変わった場合は、対象プラグインを再スキャンしてソースキャッシュを更新してください。原文、訳文、レビューの根拠が変わっていない項目のレビュー状態は引き続き有効です。

## 翻訳とレビュー

1. プラグインと翻訳言語を選びます。
2. **翻訳** に入力します。原文を残す場合は **原文を使用** を有効にします。
3. **ポップアップ項目を編集…** でドロップダウンの文字を編集し、項目数と順序を保持します。
4. 文字を確認したら、**状態** を **レビュー済み** にします。

原文や訳文が変わると、以前のレビューを再確認する必要が生じる場合があります。現在の内容を確認してからレビュー済みにしてください。

## 保存と再読み込み

`*` は未保存の変更を示します。**現在のプラグインを保存** または **すべての変更を保存** を使います。

別のウィンドウやツールでファイルが更新された場合は、必要な下書きを控えてから **翻訳ファイルを再読み込み** を実行し、最新の内容を確認して保存します。

## 公開レビューの確認

保存後、エフェクトまたは Settings を選び、**スキャン > 現在のプラグインの公開レビューを確認** を実行します。翻訳の不足、無効な内容、未レビューの項目が表示された場合は対応してください。

この操作は現在のプラグインを確認します。正式な一式のビルドには `BuildPlugins.bat publication` を使用し、ビルド処理でまとめて検証します。

## 終了または再起動

変更を保存してから、ターミナルで `Ctrl+C` を押してサービスを停止します。再び使う場合は起動コマンドを実行してください。
